# План наполнения вики Cyberpunk 2020

## Цель

Собрать русскоязычный справочник для ручного создания персонажа в Cyberpunk 2020, редакция 2.01. Рядом с основными русскими названиями указываются английские оригиналы.

Проект не должен заменять основную книгу правил. До получения письменного разрешения R. Talsorian Games публикуются только:

- оригинальные обзорные тексты и навигация;
- краткие пересказы понятий своими словами;
- названия сущностей и общеупотребительная терминология;
- структура процесса создания персонажа;
- метаданные редакции и статус проверки.

Числовые таблицы, полные перечни характеристик предметов, результаты Lifepath и близкие к оригиналу формулировки остаются закрытым backlog до ответа правообладателя.

## Инвентарь разделов

| Раздел | Содержание | Нужен для персонажа | Текущий безопасный объём |
| --- | --- | --- | --- |
| Guides | маршрут создания, чек-листы, объяснение структуры листа | да | полный авторский обзор |
| Roles | назначение роли, образ, место в группе | да | краткое оригинальное описание |
| Stats | назначение каждой характеристики | да | объяснение без таблиц и формул |
| Skills | назначение и область применения навыка | да | краткое описание; числа отложить |
| Lifepath | этапы биографии персонажа | да | инструкции и вопросы без результатов таблиц |
| Rules | начальные средства, Humanity и Empathy | да | концепции без числовых значений |
| Gear | категории бытового и профессионального оснащения | да | навигация и авторские аннотации |
| Weapons | категории оружия и смысл полей | да | без статблоков |
| Armor | категории защиты и смысл полей | да | без статблоков |
| Cyberware | категории имплантов, риски, зависимости | да | без стоимости и Humanity Loss |
| Sources | библиографическая карточка основной книги | служебный | можно публиковать |

## Приоритеты

### P0 — каркас создания персонажа

1. Сквозной маршрут создания персонажа.
2. Объяснение роли, характеристик и навыков.
3. Структура Lifepath по отдельным этапам.
4. Объяснение начальных средств.
5. Связь Empathy, Humanity и киберимплантов.

### P1 — справочные карточки

1. Роли и их место в команде.
2. Характеристики.
3. Навыки и их группировка.
4. Категории снаряжения, оружия, брони и киберимплантов.

### P2 — данные, зависящие от разрешения

1. Результаты таблиц Lifepath.
2. Полные списки профессиональных навыков.
3. Стоимость, доступность и игровые параметры предметов.
4. Формулы, пороги, модификаторы и точные числовые процедуры.
5. Полные статблоки оружия, брони и киберимплантов.

## Пакеты работ

### Batch 01 — навигационный минимум

- расширить маршрут создания персонажа ссылками на этапы;
- добавить вводную по структуре персонажа;
- добавить обзор Lifepath;
- добавить страницы про начальные средства и Humanity/Empathy;
- проверить сборку и внутренние ссылки.

Результат: читатель понимает последовательность работы, но для механики обращается к книге.

### Batch 02 — роли и характеристики

- создать по одной карточке на роль;
- создать по одной карточке на характеристику;
- использовать оригинальные краткие формулировки;
- согласовать русский глоссарий и английские названия.

Результат: можно осознанно выбрать концепцию, роль и приоритеты характеристик.

### Batch 03 — навыки

- создать инвентарь навыков;
- сгруппировать карточки по связанной характеристике;
- описать область применения своими словами;
- отдельно пометить поля, ожидающие юридического разрешения.

Результат: навигационный каталог без воспроизведения защищённых таблиц.

### Batch 04 — экипировка

- создать страницы категорий оружия, брони, снаряжения и киберимплантов;
- объяснить назначение полей карточки;
- добавить безопасные карточки с названиями и краткими аннотациями;
- не добавлять статблоки до разрешения.

Результат: каркас каталога, готовый принять проверенные данные.

### Batch 05 — разрешённые числовые данные

Запускается только после документированного ответа RTG:

- зафиксировать точный объём разрешения;
- добавить таблицы малыми проверяемыми партиями;
- в каждой карточке указать редакцию 2.01;
- провести двойную сверку с легально приобретённой книгой;
- проверить, не превращает ли совокупный объём сайт в замену книге.

## Матрица статусов

Каждый Markdown-файл проходит состояния:

1. `draft` — структура или авторский черновик;
2. `review` — терминология и факты проверены вторым участником;
3. `published` — редакционная и юридическая проверка завершены.

Числовой контент не переводится в `published`, пока разрешение RTG не приложено к проектной документации.

## Критерии проверки карточки

### Редакционные

- русский заголовок понятен, английский оригинал заполнен;
- summary короче 240 символов;
- текст написан самостоятельно, а не близким пересказом абзацев книги;
- терминология единообразна с `Docs/03-content-guidelines.md`;
- явно указана редакция `2.01`;
- нет утверждений, взятых из неофициальных или пиратских сканов.

### Технические

- frontmatter соответствует `src/content.config.ts`;
- slug уникален и записан в kebab-case;
- внутренние ссылки ведут на существующие страницы;
- Markdown проходит `astro check`;
- проект успешно собирается;
- отсутствуют `.js` и `.mjs`: конфигурация и вспомогательный код пишутся на TypeScript.

### Юридические

- отсутствуют длинные цитаты;
- отсутствуют результаты таблиц Lifepath до разрешения;
- отсутствуют числовые статблоки до разрешения;
- источник получен легально;
- карточка не заявляет официальность проекта.

## Git workflow

1. Одна ветка на пакет: `content/batch-XX-topic`.
2. Одна логическая группа карточек на commit.
3. Формат commit: `content(cp2020): add lifepath drafts`.
4. В pull request перечисляются новые и изменённые slugs.
5. Автор выполняет самопроверку по критериям выше.
6. Второй участник проверяет язык, английские названия и соответствие редакции.
7. Числовые данные получают дополнительную отметку юридической проверки.
8. Merge выполняется только после успешных `pnpm check` и `pnpm build`.

## Правила для массового наполнения

- один исполнитель работает только в назначенных каталогах;
- перед началом batch фиксируется список файлов;
- существующие правки других участников не перезаписываются;
- спорный перевод добавляется в глоссарий, а не решается локально в одной карточке;
- пробел в данных обозначается статусом `draft`, а не выдуманным значением;
- пиратские PDF, OCR-копии и случайные интернет-таблицы не используются;
- автоматическая генерация создаёт черновики, но не переводит их в `published`.

## Definition of Done первой фазы

- опубликован сквозной маршрут создания персонажа;
- созданы безопасные вводные ко всем этапам Lifepath;
- описаны понятия начальных средств, Empathy и Humanity без чисел;
- утверждён инвентарь ролей, характеристик и навыков;
- для каждой коллекции есть шаблон и правила проверки;
- сборка проходит без ошибок;
- backlog защищённых данных отделён от публикуемого контента.
